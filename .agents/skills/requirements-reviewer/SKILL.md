# Requirements Reviewer

`.agents/guide/meta/pair-learning-flow.md` を読んで進める．AI は人間の提出前に要求を代筆しない．

## 要求分析フェーズ

1. `docs/requirements.md` がなければ，AI は次のテンプレートを作成する．
2. 人間は利用者・入力・出力・正常系・異常系・制約・未決事項を記入して提出する．この時点の未決事項は、要求を確定するために確認すべき論点である。
3. AI は `review/requirements.md` を作成し、再レビューは `requirements.v2.md` のように新規作成する．

```md
# 要求分析

## 目的と利用者

## 入力と出力

## 機能要求

## 非機能要求・制約

## 受け入れ条件

## 未決事項
```

## レビューと要求合意

1. 初回レビューでは、要求の理解・構造化を採点し、曖昧さ・漏れ・未決事項を抽出する。この点数は要求分析の初回点であり、設計フェーズへの承認とは別である。
2. 未決事項ごとに、利用者から観測できる振る舞い、入力・出力、制約、受け入れ条件に影響するかを確認する。影響するものは、利用者と合意して必ず決定する。
3. 合意した内容を人間が `docs/requirements.md` の要求・制約・受け入れ条件へ反映する。最終承認前に `未決事項` は空にするか削除する。スコープ外とする事項は、対象外であることを要求として明記して閉じる。
4. 実現手段だけを選ぶ論点（内部データ型、モジュール分割、エラー型など）は、要求としての振る舞いを先に合意したうえで設計フェーズへ渡してよい。
5. AI は反映後の要求定義書を再レビューし、合意内容との一致を確認する。

採点表は「目的・利用者の明確さ 20点」「要求・受け入れ条件の完全性 35点」「入力・出力・失敗時の明確さ 25点」「制約・未決事項の整理 20点」の100点満点とする．指摘表には既存の標準列を使う。未決事項の指摘には、`要求確認`、`設計判断`、`スコープ外` の区分を記載する。

## 遷移

- 初回採点後は、未決事項の合意・反映フェーズへ進む。AI は初回採点だけを理由に設計フェーズを提案しない。
- 全指摘が `承認` または理由付き `却下` であり、利用者に確認すべき未決事項がなく、`docs/requirements.md` の未決事項が空または削除済みで、基準点を満たしたときだけ、設計フェーズを提案する．
- AI は「設計フェーズへ移行してよいですか」と人間の明示的な承諾を得るまで移行しない．
