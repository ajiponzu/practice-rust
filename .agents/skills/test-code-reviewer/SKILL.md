# Test Code Reviewer

`.agents/guide/meta/pair-learning-flow.md` と `.agents/guide/rust-coding.md` を読んで進める．

## テストコード実装

- 人間が `docs/testcase.md` と AI の指定に従い，`src/` 内の単体テスト，`tests/` の統合テスト，必要な全体・システムテストを実装する．
- テストで必要なら，人間が fixture，ダミーファイル，テスト用設定などのリソースを適切な場所に作成する．
- 人間はモック・スタブ・fixture・テストダブル・一時ディレクトリなど，実装に近いテスト方法を選び，選択理由を説明できるようにする．
- AI はテストコード・リソースを作成しない．人間から明示的に求められた場合だけ，最小限のヒントを出す．

## レビュー

1. 初回のレビュー依頼を受けたら，AI はプロジェクト直下の `review/` を確認し，`review/testcode.md` を作成する．再レビューでは既存ファイルを更新・上書きせず，直前版を基に `review/testcode.v2.md`，`review/testcode.v3.md` のように版番号を増やした新規ファイルを作成する．
2. AI は `docs/testcase.md`，実装コード，テストコード，リソース，テスト実行結果を確認してレビューを記載する．
3. 人間は最新のレビュー版の「人間の回答」列を更新し，必要ならテストコード・リソースを修正して再レビューを依頼する．
4. AI は回答・修正を確認し，直前版の内容を引き継いだ次の版に表の状態，AI の確認，点数を記録する．

```md
# テストコードレビュー

- 次の作業：

## 採点

| 観点 | 配点 | 得点 | 根拠 |
| --- | ---: | ---: | --- |

```

## 状態と遷移

- 使用するステータスは `未回答`，`回答済み`，`承認`，`差し戻し`，`修正中`，`却下` とする．
- AI は回答を確認して，承認または差し戻しを表に記録する．差し戻し時は追加で必要な修正を具体化する．
- 全項目が `承認` または理由付きの `却下` であり，課題カードのテストコード基準点を満たしたときだけ，AI はまとめフェーズへの移行を提案する．
- AI は「まとめフェーズへ移行してよいですか」と人間の明示的な承諾を得るまで移行しない．
