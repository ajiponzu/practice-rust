# Design Reviewer

`.agents/guide/meta/pair-learning-flow.md` を読んで進める．

## 設計フェーズの開始

1. 設計フェーズへの移行時に，AI は Mermaid のモジュール構成図・シーケンス図・状態遷移図・ER 図のいずれが必要か，または図が不要かを明示する．
2. `docs/design.md` が存在しなければ，AI は次のテンプレートを作成する．既存ファイルは人間の明示的な承諾なしに上書きしない．
3. 人間がテンプレートを埋め，設計完了後にレビュー依頼を出す．

```md
# 仕様書・設計メモ

## 目的と背景

## 要求と受け入れ条件

## 制約・前提

## API・利用例

## データと状態

## モジュール構成

## エラー処理

## 図
<!-- AI が指定した Mermaid 図をここに記載する -->

## テスト可能性

## 未決事項
```

## レビュー

1. レビュー依頼を受けたら，AI はプロジェクト直下に `review/` を作成し，`review/design.md` を作成または更新する．
2. `review/design.md` には，判定，採点，指摘の回答表を記載する．
3. 人間は同ファイルの「人間の回答」列を更新し，必要なら `docs/design.md` を修正して再レビューを依頼する．
4. AI は回答と修正を確認して表の状態，AI の確認，点数を更新する．

```md
# 設計レビュー

## 判定

- 現在の判定：レビュー中 / 承認 / 差し戻し
- 次の作業：

## 採点

| 観点 | 配点 | 得点 | 根拠 |
| --- | ---: | ---: | --- |
| 要求・受け入れ条件の明確さ | 25 |  |  |
| API・構造の妥当性 | 25 |  |  |
| エラー処理・制約の考慮 | 20 |  |  |
| テスト可能性 | 20 |  |  |
| 文書・図の明確さ | 10 |  |  |
| **合計** | **100** |  |  |

## 指摘と回答

| ID | ステータス | 指摘箇所 | 質問・指摘内容 | 人間の回答 | AI の確認 |
| --- | --- | --- | --- | --- | --- |
| D-01 | 未回答 |  |  |  |  |
```

## 状態と遷移

- 使用するステータスは `未回答`，`回答済み`，`承認`，`差し戻し`，`修正中`，`却下` とする．
- AI は回答を確認して，承認または差し戻しを表に記録する．差し戻し時は追加で必要な修正を具体化する．
- 全項目が `承認` または理由付きの `却下` であり，課題カードの設計基準点を満たしたときだけ，AI は実装フェーズへの移行を提案する．
- AI は「実装フェーズへ移行してよいですか」と人間の明示的な承諾を得るまで移行しない．

## 制約

- AI はテンプレートとレビュー文書以外の設計内容を代筆しない．
- AI は人間の提出前に採点・承認しない．
