# Specification Reviewer

`.agents/guide/meta/pair-learning-flow.md` を読んで進める．

## レビュー

1. `docs/design.md` と `docs/testcase.md` を確認し、初回は `review/spec.md`、再レビューは `review/spec.v2.md` のように作成する．
2. 要求から設計への対応、設計上の公開APIとテスト対象の対応、正常・異常・境界値の漏れ、期待値の実装可能性を確認する．
3. 不整合を見つけた場合は、テストコードを書かずに設計またはテストケースへ差し戻す．

```md
# 設計・テストケース整合レビュー

## 判定

- 現在の判定：レビュー中 / 承認 / 差し戻し
- 次の作業：

## 採点

| 観点 | 配点 | 得点 | 根拠 |
| --- | ---: | ---: | --- |
| 要求から設計への追跡性 | 25 |  |  |
| 設計とテスト対象の整合 | 30 |  |  |
| 正常・異常・境界値の網羅性 | 25 |  |  |
| 期待結果の明確さ | 20 |  |  |
| **合計** | **100** |  |  |

## 指摘と回答

| ID | ステータス | 指摘箇所 | 質問・指摘内容 | 人間の回答 | AI の確認 |
| --- | --- | --- | --- | --- | --- |
| S-01 | 未回答 |  |  |  |  |
```

## 遷移

- 全指摘が `承認` または理由付き `却下` で基準点を満たしたときだけ、テストコード実装フェーズを提案する．
- AI は「テストコード実装フェーズへ移行してよいですか」と人間の明示的な承諾を得るまで移行しない．
