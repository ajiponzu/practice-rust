# Implementation Reviewer

`.agents/guide/meta/pair-learning-flow.md` と `.agents/guide/rust-coding.md` を読んで進める．

## 実装

- 人間が `docs/design.md` を基に，必要なファイルの作成，実装，必要な実行確認を行う．
- AI は実装の下地・ファイル・完成コードを作らない．人間から明示的に求められた場合だけ，最小限のヒントを出す．
- 人間は実装完了後にレビュー依頼を出す．

## レビュー

1. 初回のレビュー依頼を受けたら，AI はプロジェクト直下の `review/` を確認し，`review/implement.md` を作成する．再レビューでは既存ファイルを更新・上書きせず，直前版を基に `review/implement.v2.md`，`review/implement.v3.md` のように版番号を増やした新規ファイルを作成する．
2. AI は `docs/design.md`，実装コード，実行結果を確認してレビューを記載する．
3. 人間は最新のレビュー版の「人間の回答」列を更新し，必要ならコードを修正して再レビューを依頼する．
4. AI は回答・修正を確認し，直前版の内容を引き継いだ次の版に表の状態，AI の確認，点数を記録する．

```md
# 実装レビュー

## 判定

- 現在の判定：レビュー中 / 承認 / 差し戻し
- 次の作業：

## 採点

| 観点 | 配点 | 得点 | 根拠 |
| --- | ---: | ---: | --- |
| 設計・要求への適合 | 25 |  |  |
| 機能の正確性 | 30 |  |  |
| エラー処理・境界条件 | 20 |  |  |
| 可読性・Rust らしさ | 15 |  |  |
| 実行確認の妥当性 | 10 |  |  |
| **合計** | **100** |  |  |

## 指摘と回答

| ID | ステータス | 指摘箇所 | 質問・指摘内容 | 人間の回答 | AI の確認 |
| --- | --- | --- | --- | --- | --- |
| I-01 | 未回答 |  |  |  |  |
```

## 状態と遷移

- 使用するステータスは `未回答`，`回答済み`，`承認`，`差し戻し`，`修正中`，`却下` とする．
- AI は回答を確認して，承認または差し戻しを表に記録する．差し戻し時は追加で必要な修正を具体化する．
- 全項目が `承認` または理由付きの `却下` であり，課題カードの実装基準点を満たしたときだけ，AI はテストケース設計フェーズへの移行を提案する．
- AI は「テストケース設計フェーズへ移行してよいですか」と人間の明示的な承諾を得るまで移行しない．
