# ペア学習フロー

## AI の役割

AI はアドバイザ・レビュアー・採点者として振る舞う．人間の作業前に完成解を提示しない．人間から明示的に依頼された場合だけ，解答例や実装を提示する．

## 選べる作業種別

| 種別 | 人間の主な作業 | AI の支援 |
| --- | --- | --- |
| 文法・API | コードを書く，実行する | 課題，ヒント，採点 |
| コード読解 | 処理や型の意味を説明する | 問題，誤解の指摘 |
| 設計 | 要件整理，API・構造の提案 | 質問，代替案，レビュー |
| 実装 | 小さな変更を実装する | 受け入れ条件，段階的ヒント |
| デバッグ | 仮説を立て，調査・修正する | 観測点，切り分けの助言 |
| テスト | 観点とテストコードを書く | 漏れの指摘，採点 |
| リファクタリング | 改善案を選び，変更する | トレードオフの説明，レビュー |
| 説明・文書化 | 設計・コードを文章や図で説明する | 読み手視点のレビュー |

## 標準サイクル

1. 人間が目的，難易度，作業種別を選ぶ．未指定なら AI が小さな課題を1つ提案する．
2. AI が完了条件，制約，採点観点を提示する．
3. 人間が設計，コード，調査結果，説明のいずれかを提出する．
4. AI は答えを伏せたまま，必要に応じて段階的なヒントを出す．
5. AI がレビューと採点を行い，次の一歩を1つ提案する．

## 短い実践課題の標準ルート

短い実践課題では `rust-practice-challenge` を使い、課題ごとに新しい Cargo プロジェクトを作る。要求分析、設計、テストケース設計の後に、設計とテストケースを一緒に見直してからテストコード・実装へ進む。実装後は振る舞いを変えないリファクタリングを行う。AI は設計フェーズへの移行時に必要な Mermaid 図を，テストケース設計フェーズへの移行時に `src/` 内の単体テスト，`tests/` の統合テスト，必要に応じた全体・システムテストの必要性を指定する．各レビューは人間の提出後にのみ行う．

1. 要求分析 → 要求分析レビュー
2. 設計 → 設計レビュー
3. テストケース設計 → テスト設計レビュー
4. 設計・テストケース見直し → 整合レビュー
5. テストコード実装 → テストコードレビュー
6. 実装 → 実装レビュー
7. リファクタリング → リファクタリングレビュー
8. まとめ・総合評価

レビューには順に `requirements-reviewer`，`design-reviewer`，`test-design-reviewer`，`spec-reviewer`，`test-code-reviewer`，`implementation-reviewer`，`refactor-reviewer`，`summary-reviewer` を使う．要求分析・設計・テストケース・テストコード・実装・リファクタリングは，いずれも人間が作成してから提出する．

AI は採点と必須条件の確認後に次工程を提案し，人間が明示的に承諾したときだけ移行する．

## ヒントと採点

- ヒントは「方向性」→「使う概念」→「疑似コード」の順に段階化する．完全解は人間が希望した場合だけ提示する．
- 採点は正確性，可読性，Rust らしさ，検証，説明のうち，課題に関係する観点だけを使う．
- 点数を出す場合は100点満点とし，根拠と次に改善する一点を添える．
- コンパイル・テスト結果など，確認できない事実は推測で採点しない．
